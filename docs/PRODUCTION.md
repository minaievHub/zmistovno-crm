# Переход на рабочую CRM

Рабочая версия использует Supabase Auth и PostgreSQL. Локальная база `.test-db` и демо-пароль в ней не используются. После клонирования скопируйте `.env.example` в `.env.local`, заполните ключи и создайте внутренние секреты по инструкции Telegram. `.env.local` исключён из Git. При переносе уже настроенной установки передайте существующий файл отдельно: ключ шифрования должен сохраниться.

## Первое подключение

1. Создайте проект Supabase. В его настройках API возьмите URL, publishable key и серверный service role key. Запишите их в одноимённые поля `.env.local`. Значения не публикуйте в переписке.
2. В Supabase SQL Editor выполните целиком `supabase/migrations/202609070001_crm.sql`, затем `supabase/migrations/202609070002_telegram.sql`. Применяйте один раз и по порядку. Если первая миграция уже выполнена, выполняйте только вторую. **Не выполняйте `supabase/seed.sql` в рабочей базе** — это вымышленные заявки.
3. В `.env.local` укажите `ADMIN_EMAIL`, новый `ADMIN_PASSWORD` длиной от 12 символов и `ADMIN_NAME`. В терминале проекта выполните:

   ```powershell
   $env:PATH = "$PWD\.tools\node-v24.20.0-win-x64;$env:PATH"
   npm.cmd run admin
   ```

   После успешного создания очистите `ADMIN_PASSWORD`. `SUPABASE_SERVICE_ROLE_KEY` оставьте: он нужен Telegram-модулю на сервере.
4. Для работы на этом компьютере оставьте `APP_URL=http://127.0.0.1:3000`. Для доступа родителей и сотрудников из интернета разверните CRM на сервере/хостинге и задайте публичный HTTPS-домен в `APP_URL`. Локальное посилання недоступно родителям извне.
5. Запустите production-версию из терминала проекта:

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts/start-production.ps1
   ```

   Скрипт проверяет конфигурацию, собирает приложение и запускает `next start`. Оставьте терминал открытым; для остановки нажмите Ctrl+C. Вход: `http://127.0.0.1:3000/login`, ваша почта и пароль администратора. После изменения публичных переменных окружения снова выполните этот скрипт, чтобы пересобрать клиент.

## Telegram

Заполните `TELEGRAM_BOT_TOKEN`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`. Сгенерированные ключи шифрования и секреты сохраните. После перезапуска откройте «Telegram → Підключення»: проверьте бота, авторизуйте аккаунт владельца по телефону, коду и 2FA. Для webhook нужен публичный HTTPS-домен. Подробно: [TELEGRAM.md](TELEGRAM.md).

Для запланированных публикаций запустите во втором терминале `npm.cmd run telegram:worker` с тем же Node PATH. На постоянном сервере приложение и воркер должны запускаться через process manager; на Vercel используйте cron из `vercel.json` с поддерживаемой тарифом частотой. Без работающего планировщика отложенные сообщения не отправятся.

## Проверка перед работой школы

Войдите своим администратором, создайте реальный курс и набор. Откройте ссылку регистрации в отдельном браузере, отправьте одну собственную тестовую заявку, проверьте её обработку и удалите через CRM. В отдельной Telegram-группе проверьте публикацию и запланированное сообщение. Рабочие ключи и удалённая инфраструктура пока не проверены автоматически.

Инструкция сотруднику: [USER_GUIDE.md](USER_GUIDE.md). Развёртывание на Vercel и создание менеджера описаны в [README](../README.md). После подключения выполняйте резервное копирование базы средствами своего Supabase-проекта.
