# Запуск на сервере с 2 GB RAM

Сборка выполняется в GitHub Actions. На сервере нужны Linux x64 и Node.js 24; `npm install` и `npm run build` выполнять не нужно. Для ARM-сервера этот архив не подходит.

1. Откройте репозиторий → Actions → **Build server archive** → последний успешный запуск. В разделе Artifacts скачайте `zmistovno-crm-linux-x64`. Для ручной сборки нажмите Run workflow. Артефакты хранятся 30 дней.
2. Распакуйте скачанный ZIP. Передайте содержащиеся в нём `.tar.gz` и `.sha256` на сервер. Проверьте и распакуйте:

   ```sh
   sha256sum -c zmistovno-crm-linux-x64.tar.gz.sha256
   mkdir -p /opt/zmistovno-crm
   tar -xzf zmistovno-crm-linux-x64.tar.gz -C /opt/zmistovno-crm
   cd /opt/zmistovno-crm
   ```

3. Отдельно передайте рабочий `.env.local` в `/opt/zmistovno-crm`. Не передавайте `SUPABASE_ACCESS_TOKEN` и `ADMIN_PASSWORD`: они не нужны при работе. Сохраните ключ шифрования Telegram. Задайте `APP_URL` равным адресу, по которому открываете CRM. Домен покупать не требуется; для закрытого доступа используйте SSH-туннель:

   ```sh
   ssh -L 3000:127.0.0.1:3000 USER@SERVER_IP
   ```

   При таком доступе `APP_URL=http://127.0.0.1:3000`. Открывайте этот адрес на своём компьютере. Для внешних регистраций родителей и Telegram webhook нужен доступный им HTTPS-адрес. По умолчанию CRM слушает только localhost; для reverse proxy на другой машине настройте `CRM_BIND_HOST` сознательно.
4. Запустите:

   ```sh
   chmod 600 .env.local
   node scripts/run-server.mjs
   ```

   Команда запускает CRM и Telegram-планировщик. Начальная проверка очереди может не успеть до старта приложения; следующая выполнится автоматически. Терминал должен оставаться открытым, для постоянной работы используйте systemd или существующий process manager от непривилегированного пользователя. Рабочий каталог — `/opt/zmistovno-crm`, команда — полный путь к `node scripts/run-server.mjs`.

## Обновление и настройки сборки

Распаковывайте обновление в новый каталог, передавайте тот же `.env.local`, останавливайте старый процесс и переключайте сервис на новый. Не накладывайте архив поверх старых зависимостей. База находится в Supabase, в архив она не входит. Применённые миграции повторять не нужно.

GitHub → Settings → Secrets and variables → Actions → Variables содержит только публичные `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. При смене проекта Supabase обновите их и пересоберите архив. Серверные секреты Actions не требуются и в архив не включаются.

Лимит JavaScript heap приложения — 768 MB, воркера — 128 MB. Это не лимит общей памяти процессов и не гарантия пикового потребления. Контролируйте RSS на сервере под своей нагрузкой; сборка на сервере больше не выполняется.
