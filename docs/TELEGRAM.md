# Telegram Control Center

Модуль доступний у `/telegram`, підключення — `/settings/telegram`. Admin налаштовує інтеграцію, admin і manager керують групами та публікаціями.

## Можливості

- Створення супергрупи акаунтом власника, додавання бота адміністратором, invite link, прив’язка до курсу, набору та навчальної групи. Наявні групи/канали можна підключити за chat ID або публічним username.
- Створення навчальної групи разом із Telegram та посиланням Zoom/Meet. У картках курсу й набору є створення Telegram infrastructure, у наборі — підготовка анонсу з кнопкою реєстрації, у групі — повідомлення її учасникам.
- Форматований текст, посилання, emoji, одне фото/відео/PDF або альбом до 10 фото. До п’яти URL-кнопок для тексту чи одного медіа. Перед надсиланням обов’язковий preview з переліком отримувачів.
- Вибір окремих чатів, усіх активних, каналів або чатів курсу. Чернетки, публікація зараз, відкладена публікація, зміна й скасування розкладу до початку доставки.
- Історія по кожному чату з Telegram message ID, редагування тексту/підпису, видалення повідомлень із підтвердженням, закріплення, копіювання та повторна публікація через preview.
- Назва, опис, нові invite links, запрошення із заявкою на вступ, синхронізація даних/кількості учасників/статусу бота, архівування у CRM. Архівування не видаляє реальну Telegram-групу.
- Шість редагованих шаблонів із підстановкою змінних, журнал дій, обробка заявок на вступ через webhook.

## Підключення

1. Застосуйте SQL-міграції послідовно: `202609070001_crm.sql`, потім `202609070002_telegram.sql` у Supabase SQL Editor або через ваш процес міграцій. Друга міграція створює таблиці, RLS, атомарні RPC черги та приватний Storage bucket `telegram-media`.
2. На сервері задайте змінні з `.env.example`:

   | Змінна | Призначення |
   | --- | --- |
   | `SUPABASE_SERVICE_ROLE_KEY` | Серверний доступ до черги, секретів і приватних медіа |
   | `TELEGRAM_BOT_TOKEN` | Токен бота школи від BotFather |
   | `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | Параметри власного Telegram API application для MTProto |
   | `TELEGRAM_ENCRYPTION_KEY` | Окремий випадковий ключ 32 байти в base64 |
   | `TELEGRAM_WEBHOOK_SECRET` | Випадковий секрет 16–256 символів: літери, цифри, `_`, `-` |
   | `CRON_SECRET` | Окремий довгий випадковий секрет планувальника |
   | `APP_URL` | Публічний HTTPS origin CRM без кінцевого `/` |

   Ключ шифрування можна створити командою `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`. Секрети не повинні мати префікса `NEXT_PUBLIC_`. Зберігайте ключ шифрування окремо від резервної копії БД; його втрата потребує повторної авторизації акаунта.
3. Перезапустіть застосунок. Увійдіть як admin, відкрийте Telegram → Підключення → «Перевірити підключення».
4. Для створення нових груп натисніть «Авторизувати», введіть номер власника, код Telegram та пароль 2FA, якщо запитано. Сесія шифрується AES-256-GCM у серверній таблиці. Коди й пароль не зберігаються. Номер у відповіді маскується. «Відключити» відкликає сесію та видаляє її із CRM.
5. Натисніть «Підключити webhook». Це реєструє `/api/telegram/webhook` для `chat_join_request` та `my_chat_member`. Вебхук захищений секретним заголовком Telegram. Якщо бот уже працює з іншим webhook, нова адреса замінить його.
6. Для наявної групи/каналу спочатку надайте боту права адміністратора, включно із запрошеннями, зміною інформації, публікацією/редагуванням/видаленням і закріпленням відповідно до типу чату. У новій групі це робить MTProto-адаптер. Події додавання бота виявляють чати автоматично; старі чати підключайте вручну.
7. Налаштуйте постійний планувальник, описаний нижче. Перевірте на окремій тестовій групі текст, фото, редагування, invite, заявку на вступ і публікацію на кілька хвилин уперед.

## Планувальник

Дати зберігаються в UTC, у формі обирається часовий пояс (типово Europe/Kyiv). Неіснуючий або неоднозначний час при переході літнього/зимового часу відхиляється з поясненням.

`GET /api/telegram/cron` потребує `Authorization: Bearer <CRON_SECRET>`. Один виклик обробляє до трьох доставок. RPC бере записи через `FOR UPDATE SKIP LOCKED`: одночасні воркери не отримають ту саму доставку. Скасування й зміна розкладу блокуються після початку надсилання.

- Vercel: `vercel.json` містить щохвилинний cron. Потрібен тариф, що підтримує таку частоту, та достатня тривалість Node function (до 120 секунд).
- Власний Node-сервер: разом із `npm run start` запустіть `npm run telegram:worker` через ваш process manager. Воркер читає `.env.local` і перевіряє чергу кожні 15 секунд після завершення попереднього виклику. Для іншого cron достатньо захищеного HTTP-запиту з такою самою частотою.
- `npm run demo` автоматично запускає локальний воркер з тимчасовим секретом. Поки процес зупинений, повідомлення не обробляються; після запуску прострочені завдання підхоплюються.

Невдала або непідтверджена доставка не повторюється автоматично: Telegram не надає ідемпотентного ключа для `sendMessage`. Після таймауту/падіння перевірте чат; копіювання створює нову публікацію через preview. Записи `sending`, що зависли понад п’ять хвилин, позначаються помилкою з поясненням. Частковий успіх зберігає message ID успішних доставок.

## Медіа та поточні межі

Завантаження приватні, доступні лише працівникам через авторизований маршрут. Ліміт застосунку — 4 MB на файл, JPG/PNG/WebP, MP4, PDF. Це свідомий ліміт MVP для сумісності з serverless request body. Фотоальбом не підтримує inline-кнопок; редактор пояснює це до надсилання. Текст обмежено 4096 символами, підпис медіа — 1024. Зміна опублікованого поста редагує текст/підпис; заміна медіа та аудиторії виконується через нову публікацію.

MTProto використовується для авторизації власника, створення груп і призначення бота. Усі розсилки виконує Bot API. Адаптери відокремлені від `TelegramService`. У `automation.ts` підготовлено типи майбутніх автоматизацій, AI provider та inbox; генерація AI, автоматичні правила й особистий inbox ще не реалізовані.

## Перевірка

`npm test` перевіряє SQL/RLS, атомарність черги, скасування, архіви, шифрування, очищення HTML, DST та обмеження контенту. `npm run test:e2e` перевіряє Telegram UI через явно позначений локальний демо-адаптер. Це не перевірка реального Telegram: робочі ключі та акаунт у цьому середовищі не надані. Test/demo адаптер вимкнений у production.

Офіційні джерела: [Telegram Bot API](https://core.telegram.org/bots/api), [Bot FAQ](https://core.telegram.org/bots/faq), [Telegram API application](https://core.telegram.org/api/obtaining_api_id), [Teleproto migration/API compatibility](https://docs.teleproto.dev/migrating-from-gramjs).
